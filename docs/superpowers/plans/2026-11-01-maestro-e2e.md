# Maestro E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phase-1 Maestro smoke (5 tabs) with UITestMode launch and stable accessibility ids.

**Architecture:** Launch arg `-UITestMode` skips onboarding + Health/Notifications prompts; Maestro YAML under `.maestro/` drives Simulator; `scripts/maestro_run.sh` builds, installs, runs tagged flows.

**Tech Stack:** Maestro CLI, iOS Simulator, Xcode `WorkoutTracker` scheme, SwiftUI `accessibilityIdentifier`, bash runner.

**Spec:** `docs/superpowers/specs/2026-11-01-maestro-e2e-design.md`

## Global Constraints

- Bundle ID: `com.borisdev.WorkoutTracker`
- Do not wipe user data outside UITest launch clears Maestro controls
- Sign-out ≠ wipe (ADR) — UITestMode must not call `deleteLocalData`
- Prefer EN String Catalog; assert ids over copy
- No Watch / Widget flows in Phase 1
- Do not commit unless user asks «коммит»
